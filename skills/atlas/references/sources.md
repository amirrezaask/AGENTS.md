# Source methods and Atlas adaptations

Consult this reference when changing the discovery method, not during every
baseline. Reviewed on 2026-10-28. These sources informed the investigation design;
Atlas's local document and authorization conventions take precedence. No external
skill installation or network access is required to use Atlas.

| Source | Useful method | Atlas adaptation |
| --- | --- | --- |
| [smallnest: code-to-spec](https://github.com/smallnest/goal-workflow/blob/master/skills/code-to-spec/SKILL.md) | Inspect manifests, entry points, schemas, integrations, tests and gaps | Use the breadth of evidence; replace a single SPEC and repeated save approvals with the agreed document map and existing authorization |
| [dceoy: speckit-baseline](https://github.com/dceoy/speckit-agent-skills/blob/main/skills/speckit-baseline/SKILL.md) | Translate technical behavior into actor scenarios and requirements | Keep observed behavior separate from accepted intent; do not infer a required cache or guaranteed notification from one implementation pattern; omit Spec Kit scaffolding |
| [Jeffallan: Spec Miner](https://github.com/jeffallan/claude-skills/blob/main/skills/spec-miner/SKILL.md), [analysis process](https://github.com/jeffallan/claude-skills/blob/main/skills/spec-miner/references/analysis-process.md), [checklist](https://github.com/jeffallan/claude-skills/blob/main/skills/spec-miner/references/analysis-checklist.md) | Search registrations, models, auth, validation, integrations and jobs; write checkable observations | Adapt searches to actual stack and wiring; include bypass paths, state authority and a whole-scope coverage frontier |
| [Investigate Codebase](https://github.com/Data-System-School/agent-skills/blob/main/investigate-codebase/SKILL.md), [large-codebase orientation](https://github.com/Data-System-School/agent-skills/blob/main/investigate-codebase/references/orient-large-codebase.md) | Responsibility maps, thin vertical traces, evidence labels and counterexample checks | Use bounded passes for context control; initial samples do not establish complete baseline coverage |
| [arc42 building blocks](https://github.com/MSiccDev/arc42-toolkit/blob/main/skills/arc42-section-05/SKILL.md), [runtime view](https://github.com/MSiccDev/arc42-toolkit/blob/main/skills/arc42-section-06/SKILL.md), [toolkit](https://github.com/MSiccDev/arc42-toolkit) | Responsibility/interface hierarchy, selective deeper views and important failure scenarios | Keep structural and runtime accounts consistent; avoid fixed scenario counts, mandatory diagram tooling or treating discovered cycles as permission to refactor |
| [C4 architecture workflow](https://github.com/wshobson/agents/blob/main/plugins/c4-architecture/commands/c4-architecture.md), [official C4 guidance](https://c4model.com/diagrams) | Relate implementation, logical components, runtime units and system context | Use each level when it explains behavior; avoid documenting every directory and function or dispatching agents automatically |
| [Microsoft domain glossary](https://github.com/microsoft/devsquad-copilot/blob/main/.github/plugins/devsquad/skills/domain-glossary/SKILL.md) | Canonical terminology, ambiguity flags and intentional translations | Put shared vocabulary in domain.md and keep area-specific meanings and observed/accepted status explicit |
| [Addy Osmani: documentation and ADRs](https://github.com/addyosmani/agent-skills/blob/main/skills/documentation-and-adrs/SKILL.md) | Preserve reasons, constraints, alternatives and tradeoffs | Store reasoning in Factory task plans/debriefs and link from current specs; omit a mandatory decision directory |
| [mblode: codebase architecture](https://github.com/mblode/agent-skills/blob/main/skills/codebase-architecture/SKILL.md), [domain-informed boundaries](https://github.com/mblode/agent-skills/blob/main/skills/codebase-architecture/references/deepening-existing.md) | Recover business language and identify scattered rules and leaking seams | Use as evidence for documentation boundaries; discovery does not authorize deepening/refactoring or guardrail installation |
| [Magnus: software architecture analysis](https://github.com/magnus919/agent-skills/blob/main/software-architecture-analysis/SKILL.md), [coupling lenses](https://github.com/magnus919/agent-skills/blob/main/software-architecture-analysis/references/coupling-modularity-and-decomposition.md), [data/workflow ownership](https://github.com/magnus919/agent-skills/blob/main/software-architecture-analysis/references/data-ownership-and-workflow-analysis.md) | Inspect coupling, authoritative writers, transaction boundaries and reconciliation | Describe present boundaries and incomplete recovery with evidence; omit redesign and clean-room migration workflows |
| [Diátaxis](https://diataxis.fr/) | Organize content around reader needs | Keep specifications focused on understanding and reference; link operational procedures and avoid turning them into tutorials |

The upstream skills solve different problems and their output conventions differ.
Atlas combines evidence collection, responsibility-based decomposition and actor
tracing under the agreed filesystem contract. Avoid adopting an upstream rule
unless it improves that contract and preserves ADMIN's authorization boundaries.
