## Request and outcome

Implemented [the approved Atlas brief](../tasks/atlas/BRIEF.md) and
[plan](../tasks/atlas/PLAN.md): a separate specification skill with explicit
`/atlas` initialization, discovery prompts for existing codebases, eight
templates, Factory integration and matching AGENTS/install conventions.

Atlas's six root documents live directly under docs; areas own rules/contracts,
workflows explain actor flows, and task plans/debriefs retain decision reasoning.
Historical specs remain in place. Factory uses targeted maintenance without
implicitly initiating a full project baseline.

## Work and decisions

- Reviewed the source skills listed in Atlas's
  [maintained source reference](../../skills/atlas/references/sources.md).
  Adapted responsibility maps, evidence labels, state authority, selective
  structural views, actor tracing and counterexample checks. Did not import
  upstream directory layouts, automatic delegation, fixed scenario counts or
  refactor workflows.
- Added discovery, area, workflow, synthesis, document and maintenance guides.
  Their prompts inspect alternate actors/writers, wiring, async continuation,
  configuration, incomplete effects, rule authority and investigation coverage.
- Added explicit-only invocation policy and documented `/atlas [path or scope]`.
  Host selection can require `$atlas` or `/skills` plus the literal command;
  this change does not register a new host command parser.
- Moved the canonical area template from Factory to Atlas. Selected installs
  include both skills; the installer migrates the former Factory alias safely.
- Updated affected historical specification requirements under ADMIN's approved
  ownership/layout change. Added the new [Atlas area](../areas/atlas.md) without
  migrating unrelated historical documents.

## Independent behavioral exercise

An independent agent created a compact TypeScript ecommerce monorepo with API
registrations, workers, scheduled jobs, shared persisted state, payment adapters,
operator replay, configuration variants, historical requirements and unrelated
prototypes. It applied Atlas to produce actual documentation in an isolated
temporary directory, then compared the output to the implementation.

Reported observations:

- Normal reservation guarded availability; admin and legacy paths allowed
  negative stock. The output preserved accepted INV-001 and exposed the conflict.
- Callback deduplication persisted before event publication; failure and retry
  could acknowledge an event that never propagated. The output challenged the
  README's exactly-once claim rather than copying it.
- Missing HTTP binding, scheduler execution and external event pump remained
  explicit evidence limits. Unregistered prototypes stayed outside shipped scope.
- Executed local scenarios covered reservation success/rejection, admin and
  legacy overdraw, callback publish failure/retry, fake payment and order
  completion. No external provider calls were made.
- A successful npm test command discovered zero tests; the output reported no
  regression coverage. Links and rule anchors resolved; contracts remained in
  areas, and decision rationale linked the existing task.
- A scoped schedule change initially left an old value in an area overview.
  A consistency search caught it. Added explicit maintenance instructions to
  search old values, names and semantic equivalents across current documentation.

The evaluator removed its fixture and output. This report retains the observations
as reported evaluation evidence, not independently replayable raw traces. One
agent both constructed and exercised the synthetic fixture. This provides bounded
behavioral evidence; it does not establish discovery performance or completeness
on a production-scale monorepo, or invocation routing in every agent host.
