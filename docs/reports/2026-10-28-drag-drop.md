## Request

ADMIN approved [the brief](../tasks/done/drag-drop-and-larger-modal/BRIEF.md) replacing
status selectors and buttons with drag/drop, and then requested an 80% width,
90% height modal. [Plan](../tasks/done/drag-drop-and-larger-modal/PLAN.md).

## Outcome and Decisions

Cards use native drag/drop; their grip additionally handles Pointer Events for
mouse/touch. Destination columns highlight, saving marks the board busy, and
success reloads from the authoritative task files. Focus is restored to the
moved task. Failed requests show recovery guidance without claiming success.
Keyboard users pick up a card/grip with Space or Enter, choose a column with
Left/Right, confirm with Enter, or cancel with Escape. Document titles still
open the reader. The old selector and submit button are absent.

The existing token/origin/status write endpoint is reused. CSP explicitly allows
same-origin fetch for the client update. No consumer runtime dependency was added.
JSDOM is a development dependency only, for exercising the actual served browser
code with DOM events against an isolated copied server and task files.

The task modal is 80vw by 90dvh. Header/tabs stay fixed while document content
scrolls. Updated specs and Factory guidance reflect ADMIN's authorized changes.
The running demo has the new asset; its six sample task documents and user status
edits were preserved. The preview remains running at http://127.0.0.1:4310 as
requested; no additional preview instance was left running.

## Findings and Limitations

DOM interaction tests run the served client code and verify persisted TASK.md
results, but do not establish real-browser layout, physical drag feel, touch
hardware behavior, or computed modal geometry. Browser automation was unavailable
in this turn. No newly rendered screenshot is claimed. Same-column/cancelled
moves do not write; this version changes status, not card ordering within a column.
